# DevOps Task 4: Version-Controlled Project with Git

## Overview
This project demonstrates Git and GitHub best practices as part
of the Elevate Labs DevOps Internship Task 4.

## Objectives
- Initialize and manage a Git repository.
- Use main, dev, and feature branches.
- Practice pull requests and merging.
- Maintain a README and .gitignore.
- Create version tags.
- Document the workflow using Markdown.

## Tools
- Git
- GitHub
- Ubuntu on WSL

## Branching Strategy
- main: stable project version.
- dev: integration and development branch.
- feature: isolated changes before integration.

## Project Structure
- README.md: project overview and instructions.
- .gitignore: files excluded from version control.
- docs/git-workflow.md: Git workflow documentation.
- docs/execution-logs.md: task execution record.

## Workflow
1. Create a Git repository.
2. Create and use development branches.
3. Commit changes with descriptive messages.
4. Open pull requests on GitHub.
5. Merge approved changes.
6. Create a version tag.
7. Verify the final repository.

## Learning Outcomes
Understand version control, branching, commits, pull requests,
merge conflict resolution, Git tags, and repository hygiene.
